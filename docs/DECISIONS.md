# Architectural & Design Decisions (R8)

Rule: One line per non-obvious decision. Format: `[DEC-XXX] <Decision>: <Rationale>`.

---

- **[DEC-001]** Monorepo using native npm workspaces: Minimalist setup avoiding external monorepo tools while preserving strict TypeScript boundaries.
- **[DEC-002]** Hermes API authentication verified as HTTP Bearer token: Confirmed via official documentation (`GET /v1/capabilities` and profile `.env` configuration).
- **[DEC-003]** 104 granular traceability requirements cataloged: Spans all functional, architectural, security, state matrix, and acceptance requirements.
- **[DEC-004]** Single dispatcher architecture: Office server dispatches tasks and tracks runs; agents do not communicate peer-to-peer.
- **[DEC-005]** HermesClient dual-implementation abstraction: Modular switch between `MockHermesClient` and `RealHermesClient` controlled via `HERMES_MODE`.
- **[DEC-006]** Telegram authentication verification: Enforce 3600-second maximum auth age and timing-safe comparison (`timingSafeEqual`) to prevent replay and timing attacks.
- **[DEC-007]** Mock Hermes Server uses Node native `node:http`: Zero extraneous dependencies in dev tooling, preserving strict compliance with Section 4 allowed stack and Rule R4.
- **[DEC-008]** Phase-aware Gap Check executes natively with Node 22 `--experimental-strip-types`: Direct TypeScript execution for scripts without additional build lag or bundler drift.
- **[DEC-009]** SQLite migration path fallback mechanism: Migrator checks both `__dirname/migrations` and `src/db/migrations` to ensure transparent execution from both TypeScript source and compiled `dist/`.
- **[DEC-010]** Explicit 64-character hex regex validation for Telegram initData hash: Prevents Node.js `Buffer.from(hash, 'hex')` from silently ignoring invalid trailing characters.
- **[DEC-011]** Custom Zod preprocessor for environment boolean parsing: Ensures string `'0'` evaluates to `false` and `'1'` to `true`, preventing false security aborts on `DEV_AUTH_BYPASS`.
- **[DEC-012]** Dispatcher run event listener cleanup pattern: Stream subscription unbinds on terminal events (`run.completed`, `run.failed`, `run.cancelled`) to prevent memory leaks during long-running server uptime.
- **[DEC-013]** Web client SVG percentage overlay coordinate system: Avoids WebKit/iOS `<foreignObject>` rendering artifacts by using proportional percentage coordinates for Framer Motion avatars on top of the SVG floor plan.
- **[DEC-014]** Telegram WebApp official script with error-safe degrading wrapper: Direct `<script src="https://telegram.org/js/telegram-web-app.js">` without wrapper SDK, guarded by try/catch feature detection for all TMA capabilities.
- **[DEC-015]** Dev environment TMA mock injection: Automatically injects valid simulated Telegram WebApp object with test initData in development to enable browser testing outside Telegram.
- **[DEC-016]** Low-power mode three-tier detection: Combines hardware concurrency `<= 4`, device memory `<= 4`, and `prefers-reduced-motion` media queries with user manual toggle persistence in `localStorage`.
- **[DEC-017]** Fastify static asset bypass in authHook: Excludes non-`/api/` paths from Telegram HMAC auth so static frontend SPA bundles are served directly without breaking Rule S1.
- **[DEC-018]** Hash routing synchronization in TMA web shell: Uses `window.location.hash` (`#tasks`, `#inbox`, `#reports`, `#more`) synchronized with Zustand and `Telegram.WebApp.BackButton` to enable seamless deep linking and back-button navigation without a heavy router library.
- **[DEC-019]** Lightweight safe Markdown rendering: Custom zero-dependency regex-based Markdown renderer (`MarkdownView.tsx`) sanitizes HTML tags and renders bold, headings, lists, code, and blockquotes without pulling external dependencies outside Section 4.
- **[DEC-020]** Anti-hallucination prompt and Zod schema validation: Backend generates strict prompt citing only verified database KPI numbers, enforces JSON schema (`summary_md`, `insights[]`, `risks[]`, `actions[]`), validates with Zod, retries once on schema error, and returns 422 if unvalidated per Rule REQ-079.
- **[DEC-021]** Agent-sourced KPI explicit unverified labeling: Any KPI entry originating with `source: 'agent'` is explicitly tagged as `agent (unverified)` in system prompts and displays an amber warning badge in the UI per Rule REQ-078 & REQ-079.
- **[DEC-022]** Mock Hermes run auto-progression for polling callers: Added background run progression to `MockHermesServer` so polling endpoints like `/api/reports/generate` complete and return valid output without requiring an open SSE connection.
- **[DEC-023]** Deterministic SOUL.md generator with 9 standard sections: Implemented in `packages/shared/src/soul.ts` ensuring exact adherence to official Hermes profile structure (Identity, Mission, Responsibilities, Tone & Style, Operating Rules, Boundaries, Approval Policy, Output Format, Reporting Cadence).
- **[DEC-024]** Client-side VPS Hiring Package with verified commands: Generates copyable CLI commands for the owner's terminal without automatic shell execution (complying with Rule R11 & S6), and marks unverified commands as `// TODO(verify)`.
- **[DEC-025]** Telegram Notification Service via sendMessage: Uses direct HTTP POST to Telegram Bot API `/sendMessage` with Markdown formatting and inline `web_app` button to open the virtual office; strictly avoids `getUpdates` or `setWebhook` per Rule REQ-011.
- **[DEC-026]** Code modularization under 300 lines for Rule R5: Decomposed large components across `apps/web` and `apps/server` (Reports, Tasks, AgentSheet, Soul, Office store, server tests) into focused sub-modules to ensure 100% compliance with strict Rule R5 (< 300 lines per file).
- **[DEC-027]** Node 22 Slim Multi-Stage Containerization: Used `node:22-slim` for the runner stage to provide pre-compiled glibc binaries for `better-sqlite3`, native `--experimental-strip-types` TypeScript execution without transpilation lag, non-root user `appuser`, and persistent volume on `/data`.
- **[DEC-028]** Host Gateway Hermes Network Bridge: Configured `host.docker.internal:host-gateway` in container to reach the host Hermes API on port 8642 securely without exposing port 8642 to the public internet.
- **[DEC-029]** Single source of truth for office layouts in packages/shared: Room coordinates, lounge slots, and pure function `getAgentPlacement(agent, status, slot)` serve both 2D SVG Map and 3D Scene, eliminating duplicate layout configuration (Rule 9.1).
- **[DEC-030]** Lazy dynamic loading of 3D bundle: Loaded via `React.lazy(() => import(...))` on toggle to prevent inflating initial SPA chunk, yielding a 222.21 KB gzip 3D chunk well within the 700 KB budget (Rule 9.2 & REQ-118).
- **[DEC-031]** Strict named imports for Three.js without wildcard imports: Enforces named imports (`import { Vector3, PerspectiveCamera } from 'three'`) preventing tree-shaking failures per Rule 4B.
- **[DEC-032]** 100% procedural 3D primitives and zero remote assets: All room furniture, neon materials, and low-poly characters built from primitives with zero remote CDN textures, complying with CSP (Rule 9.4).
- **[DEC-033]** Demand-driven rendering and hardware quality tiers: `frameloop="demand"`, DPR capped [1, 1.5], antialias disabled on low-power devices, and pause on hidden tab or open sheet (Rule REQ-114 & REQ-116).
- **[DEC-034]** WebGL context loss automatic recovery: Listens to `webglcontextlost` and falls back immediately to 2D view with dismissible notification to prevent black-screen hangs (Rule REQ-117).
- **[DEC-035]** Separation of public agent representation and server-only Hermes endpoints: Defined `AgentPublicSchema` (with `endpoint_configured: boolean`) for all API responses and client store data, stripping internal `hermes_base_url` and `api_key_env` to strictly enforce Rule S4 (browser never sees Hermes URLs or server secret variable names). Client bundle verified with zero hits for internal IPs or key names.
- **[DEC-036]** Strongly typed Fastify instance decoration: Created `apps/server/src/types/fastify.d.ts` module augmentation for `fastify.db` and `fastify.dispatcher`, eliminating all `(fastify as any)` casts and removing all `eslint-disable` comments across route handlers (Rule R5 & F-09).
- **[DEC-037]** Modular gap-check architecture (C3a..C3h) with passing and failing fixtures: Decomposed gap-check into 8 separate modules under `scripts/gap-check/` with automated passing and failing test fixtures in `scripts/gap-check/__tests__/gap-check.test.ts` to strictly satisfy Rule FR3 and verify that missing endpoints, tables, env vars, or i18n keys fail non-zero.
- **[DEC-038]** Hermes Gateway resilience and SSE drop recovery: Implemented configurable `HERMES_TIMEOUT_MS` (504 response on slow Hermes) and automatic exponential backoff retry (max 5) on dropped SSE streams, falling back to `GET /v1/runs/{id}` to ensure agents never get stuck in 'working' or 'thinking' states.
- **[DEC-039]** Chat history persisted as a gateway session pointer, not a local table (Tahap 8): Stores the Hermes `session_id` per agent (`agents.session_id`, migration 003) and lists messages via `GET /api/sessions/{id}/messages`, avoiding a second divergent copy of history; falls back to stateless `/v1/chat/completions` when no session exists (STUB-006), with the UI stating "Belum ada percakapan" instead of fabricated welcome text.
- **[DEC-040]** SSE contract locked against a real production capture (Tahap 8 / STUB-004): `docs/samples/live_vps_stream_frames.jsonl` (17 frames captured live from `/api/stream` during a real run) is asserted by `apps/server/src/services/live_sample.test.ts`, replacing reliance on purely hand-written fixtures for the named-event contract (`data.type` === SSE event name).
- **[DEC-041]** VPS gateway fixed with a 1-line local patch instead of `hermes update`: The `/v1/skills` 500 (`_find_all_skills(include_editorial=True)` kwarg never accepted) exists identically in release v0.21.7 and upstream main, so updating would not fix it; the call was patched in place (backup `.bak-20261013`, undo diff `/root/skills-fix.patch`) and the gateway restarted — pending an upstream fix.
- **[DEC-042]** Character models replaced with Kenney *Mini Characters 1.0* (CC0): The Quaternius pack rendered as near-black pawns because its palette is authored at `Skin` ≈ 0.013 (a silhouette style, not a bug), and it could not be tinted per agent; Kenney's pack is textured, shares one art style with the existing Kenney furniture and street tiles, and embeds its `colormap.png` as a data URI, so 12 models stay self-contained and same-origin (Rule 9.4) with no `.bin` sidecars.
- **[DEC-043]** One agent identity across 2D and 3D: `avatar_style.character` is the single source, validated server-side against `CHARACTER_MODEL_IDS` in `packages/shared/src/characters.ts`; the department only supplies the default. The Tahap 9 accessory glyphs were removed rather than wired up — they were a second identity that never reached the 3D character — and the agent's name is now always shown (70 px, narrowing to 38 px in lounge slots) instead of being hidden with the accessory.
- **[DEC-044]** Office speech bubbles read one shared rule set: `packages/shared/src/speech.ts` owns normalisation, clipping and TTL, and both the 2D sprite and the 3D character consume it, so the two views cannot drift (Rule 9.1). The bubble only appears after the agent has actually spoken in the chat sheet, expires on its own (Rule C7), and never renders as an empty box; the `frameloop="demand"` canvas is invalidated on each expiry tick so the change is actually drawn.
- **[DEC-045]** Room shape, floor treatment and glazing live in `packages/shared/src/roomVariants.ts`, not in either renderer: the 2D map draws `roomShapePoints` as an SVG polygon and the 3D scene draws `roomShapeBoxes` as slabs from the same numbers, so a room cannot look like one thing in 2D and another in 3D (Rule 9.1). Light-surface tokens only, so the theme guard stays green.
- **[DEC-046]** SkillsModal is search-and-read only: it adds a name/description filter with an honest "x of y" count and an explicit empty state, and deliberately ships no enable/disable toggle or save button because the gateway exposes no write endpoint for skills — an invented control would be a dead end (Rule C7).
- **[DEC-047]** `data:` in `connect-src` is load-bearing for character textures, not a convenience relaxation: the Kenney GLBs embed `colormap.png` as a `data:image/png` URI and three.js loads it through `ImageBitmapLoader`, which uses `fetch()` — so the texture is a connect-src request, not an img-src one. Without it the loader's `catch()` swaps in a default white texture and every agent renders as an untextured grey blob while geometry, skinning and all 32 clips keep working (which is why the suite stayed green). `data:` grants no network access, so Rule 9.4 still holds — `https://example.com` remains blocked under the fixed policy. Pinned by three directive-parsing assertions in `apps/server/src/server.test.ts`, each proven RED by temporarily removing the token.
- **[DEC-048]** The 3D name label narrows, it never disappears: `showLabel` on `Agent3D` selects the wide pill (92 px) or the compact one (54 px), exactly as `Avatar.tsx` does in 2D (Rule 9.1). Wrapping `<Html>` in `{showLabel && …}` meant every idle agent without a selection rendered nameless, silently breaking the Tahap 17 promise that an agent is always identifiable. Both renderers now read `CHARACTER_MODEL_LABELS` from the same manifest, so the model name under the agent cannot drift between views.
- **[DEC-049]** Gait is measured off the GLBs, never guessed, and the body is driven at the clip's own speed: the `walk` clip is a mirrored scissor (verified `yLeft === yRight`, `zLeft === -zRight` on every sample), hip 0.176 units above the sole, 60° swing either side, so the feet pass 0.305 units apart twice per 0.667 s cycle — 0.916 units/s in pack scale, 1.155–1.385 units/s after `prepareForScene` scales bodies up to height 1.0; `WALK_SPEED = 1.28` is that mean. The body advances `approach(0, gap, WALK_SPEED * delta)` and `gaitFor(speed)` pays for any other speed with `timeScale` (clamped 0.35–1.6) instead of sliding the feet — the old `lerp(target, delta * 6)` ran the body at ~3 units/s against a 1.28 clip, and that 2.4× mismatch is what the owner saw as unnatural walking. Idle agents now stand, walk to a nearby spot and walk back (`patrol`), so the 180° turn happens while stationary rather than mid-stride.
- **[DEC-050]** Timeout chat streaming & perlindungan runaway task: TTFB 60s dan total 300s dipisahkan dari `HERMES_TIMEOUT_MS` (30s panggilan pendek). Stream kosong (0 byte) diperlakukan sebagai galat provider bukan sukses hampa, dan `streamEvents` / `dispatcher.runTask` dipasangi batas 900s untuk mencegah task menggantung tanpa akhir.
- **[DEC-051]** Base URL `/v1` disaring satu kali, bukan per-lapis (Tahap 20 / ST-1): `stripApiSuffix()` menghapus `.../v1` atau `.../api/v1` di ekor string, lalu dipanggil di `normalizeBaseUrl` (param agent), `resolveAgentBaseUrl` (fallback server `HERMES_BASE_URL`), `probeModels`, dan `config.ts`. Dua lapis sama-sama menyusulkan `/v1` sehingga `openrouter.ai/api/v1/v1/models` selalu 404 — penyebab laporan awal. Menambah koreksi di satu tempat saja akan membuat bug pindah ke lapis lain, jadi kontraknya adalah "siapa pun yang membentuk URL menyaring ekornya sendiri".
- **[DEC-052]** Daftar model hanya baca dari API key milik agen (Tahap 20 / ST-2 & ST-3): `GET /api/agents/:id/models` membaca `model` endpoint di server dan mengembalikan `{ models: [...] }` tanpa pernah mengirim balik URL internal, nama variabel kunci, atau isi kunci (Rule S4). `api.listAgentModels()` memakai jalur `modelsRequest()` terpisah karena respons bisa berupa 502 teks polos ketika gateway sedang mati — melewatinya lewat `request()` yang sudah ada akan melempar `Error('API error 502 … unauthorized')` dan menutupi `listError` yang jujur.
- **[DEC-053]** Endpoint mengirim string kosong secara eksplisit (Tahap 20 / ST-4): `''` berarti "ikuti pengaturan server", field yang tidak dikirim berarti "jangan ubah". Field kedua kontrak inilah yang dulu membuat tombol `Ikuti Server` mustahil ditekan. Status dibaca dari `endpoint_configured` milik `AgentPublicSchema` (server), bukan state lokal, sehingga label tidak bisa berbeda dengan keadaan sebenarnya.
- **[DEC-054]** Daftar model urut abjad dengan filter dan cap render, tanpa input ketik (Tahap 20 / ST-5): menu A-Z + kotak filter + model aktif dipin di baris pertama + maksimum 60 baris dirender dengan jumlah tersembunyi disebut apa adanya. Kolom `input` untuk mengetik nama model sengaja tidak dibuat — nama model buatan gateway tidak terdaftar akan gagal diam-diam di rute chat, dan kegagalan seperti itu harus terlihat di daftar resmi saja.
- **[DEC-055]** Prioritas model per agen disimpan di tabel `settings`, bukan migrasi (Tahap 20 / ST-6): kunci `agent_model_priority:<id>` berisi JSON array (maksimum 5, urutan = percobaan pertama sampai terakhir), divalidasi ulang saat dibaca lewat `readModelPriority()` sehingga data lama yang terpotong atau duplikat dinormalisasi di jalur baca. Rantai gagal dicatat sebagai `agent.model_fallback` `{from,to}` pada setiap langkah, dan model agen utama (`agents.model`) TIDAK pernah diganti — fallback hanya fakta percobaan, bukan pengaturan baru.
- **[DEC-056]** Fallback tidak pernah berpura-pura menjadi mode legacy: `withModelPriority()` hanya mengulang pada status 402/400/404 yang benar-benar menyebut model/deployment, dengan status dibaca HANYA dari awalan pesan (`Hermes chat error: 404`) sehingga `401` berisi teks "model 404" tidak memicu ulang. Run yang sudah menerima model `run_id`, stream yang sudah memancarkan data parsial, timeout, dan status HTTP lain berhenti di situ — kalau seluruh rantai habis, `ModelPriorityExhaustedError` naik ke rute sehingga pemilik melihat `gateway_error` yang jujur, bukan kembalinya kueri ke mode non-prioritas yang akan mengulang percobaan. Model yang benar-benar dipakai ikut tercatat di `agent_runs.model` lewat `onRunId(runId, actualModel)`.
- **[DEC-057]** Tombol Hentikan menjamin hasil, bukan sekadar niat: `stopTask()` selalu menutup task menjadi `cancelled` — termasuk saat gateway tidak terjangkau (`run_id` null, `fetch failed`) — dan galat hubungan dilaporkan lewat `gateway_error` pada respons 200, bukan 500. Penyebab lama terbukti bertumpuk: tanpa penjaga, gateway mati menghasilkan 500 dengan DB tertinggal `running`; tanpa `run_id` membalas 200 tanpa mengubah apa pun; `AgentSheet` menelan sisanya di `catch {}`. `stopTask` juga idempoten (status terminal → no-op sukses), sehingga menekan dua kali tidak mengirim panggilan gateway kedua.
- **[DEC-058]** Nama kolom PATCH difilter dua lapis — di rute (zod `.strict()`) dan di repo (`UPDATABLE_TASK_COLUMNS`) — bukan sekadar divalidasi tipe: rute memutus permintaan jahat lebih awal, sementara lapisan repo menjamin tak ada jalur tulis lain yang membawa kunci mentah ke SQL. Tanpa lapisan kedua, `{"status = 'cancelled', title": "SUNTIK"}` tersusun menjadi `title = :0, status = 'cancelled', title` dan benar-benar mengubah data (dibuktikan 200 sebelum perbaikan, 400 sesudahnya).
- **[DEC-059]** Kolom `Cancelled` dan `Failed` ikut dirender di papan Tasks, dan `DELETE /api/tasks/:id` menyertakan SSE `task_deleted`: task yang berhenti tanpa kolomnya sendiri tampak *hilang* (padahal berhasil dihentikan), dan tanpa event penghapusan kartu lama tertinggal di layar sampai muat ulang. `POST /run` kini menolak dengan 409 bila masih `running` karena dispatcher menimpa `run_id`, yang akan membuat run lama kehilangan jalan untuk dihentikan.
